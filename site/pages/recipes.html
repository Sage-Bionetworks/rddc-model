FHIR bundles from synthetic data

Synthea test patients, exported as one FHIR collection Bundle per patient. Three things to notice:

  • synthetic: true on the batch tells validators there are no real people, which relaxes identifier checks to warnings.
  • The subject IDs are FHIR Patient.identifier values, so each row needs identifierSystemUri.
  • A FhirBundleFile must list its subjectIds and bundleType.

Registry with a data dictionary

A natural history registry with two tables, a data dictionary, a join, and a project-specific extension.

  • Tables may be CSV, TSV, Parquet, JSON or JSON Lines.
  • The data dictionary is a DocumentationFile. Its about points to the record sets it documents.
  • Record sets give the columns typed fields, a key, and a references link from visits.patient_id to patients.patient_id.
  • additionalProperty carries a namespaced extension, ext:ta2_site_a:cohort.

Clinical notes

Each clinical note goes through text de-identification before lane 4. A ClinicalDocumentFile must list its subject. This batch sets containsFreeText: true to request the scan. The scanned PDF also has an informational processing hint; any value used for pipeline decisions must be a defined schema field.

Genomics

Whole-genome sequencing for one proband: paired FASTQ reads, a CRAM alignment with its index, and a VCF.

  • Every genomics file states its assay, here wgs, from a fixed list mapped to OBI assay terms. platform is optional. Alignments and variants also require referenceGenome.
  • Read pairs point to each other with pairedWith; the index points to its alignment with indexOf.
  • Gzipped FASTQ and VCF set compression: gzip.
Media types for genomics files

FASTQ, BAM, CRAM, VCF and their indexes have no registered IANA media types. Genomics files use text/plain for the text formats and application/octet-stream for the binary ones, and the class says which format it is. BAM, CRAM and BCF compress internally, so they leave compression unset.

Images and video

Facial photographs and gait videos contain biometric identifiers. Here, the acquisition table has none, so the batch sets containsBiometricIdentifiers: false. The video overrides it to true. Files with biometric identifiers stay in the trusted research environment.

The photograph uses FacialImagingFile, which always counts as biometric whatever the batch default, so it does not set the flag; the schema rejects it if it does. Its assay is photography; a 3D facial scan uses the same class with surface_scan_3d, as an OBJ, STL, glTF or PLY model. The acquisition table is a DocumentationFile whose about points to the photograph.

Consent

A consent batch uses interaction: consent. Every subject row carries a consentRef, and the batch may include ConsentFiles listing the subjects they cover. What a consent batch must contain beyond this is still an open question for the GOVERN register specification.

Restriction

A restriction looks like a withdrawal: no data files, a non-empty subject table and a noticeRef. The notice registered with GOVERN holds the restriction terms.
