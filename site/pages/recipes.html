Recipes by data type

Complete metadata sidecars for each supported data type. The data class pages explain each class and show a valid file object; these recipes show complete sidecars, with their file sets, subjects and sensitivity. Their IDs, paths, sizes and checksums are placeholders for actual batch values. The site build validates every download against JSON Schema. Completed sidecars also need validation against the batch files before upload.

FHIR bundles from synthetic data

Synthea test patients, exported as one FHIR collection Bundle per patient. Key points:

  • synthetic: true on the batch tells validators there are no real people, which relaxes identifier checks to warnings.
  • The subject IDs are FHIR Patient.identifier values, so each row needs identifierSystemUri.
  • A FhirBundleFile must list its subjectIds and bundleType.

Registry with a data dictionary

A natural history registry with two tables, a data dictionary, a join, and a project-specific extension.

  • Tables may be CSV, TSV, Parquet, JSON or JSON Lines.
  • The data dictionary is a DocumentationFile. Its about points to the record sets it documents.
  • Record sets give the columns typed fields, a key, and a references link from visits.patient_id to patients.patient_id.
  • additionalProperty carries a namespaced extension, ext:ta2_site_a:cohort.

Clinical notes

Clinical notes undergo text de-identification before further processing. A ClinicalDocumentFile must list its subject. This batch sets containsFreeText: true to request the scan. The scanned PDF also has an informational processing hint; any value used for pipeline decisions must be a defined schema field.

Genomics

Whole-genome sequencing for one proband: paired FASTQ reads, a CRAM alignment with its index, and a VCF.

  • Every genomics file states its assay and sequencing platform, here wgs on illumina, and the instrument model in platform. Alignments and variants also give referenceGenome.
  • Read pairs point to each other with pairedWith; the index points to its alignment with indexOf. Both must resolve to files in the same sidecar.
  • The files are grouped in a FileCollection file set, and every file lists the proband in subjectIds.
  • Reads and alignments name their format, FastqFile and CramFile; the variant calls are a GermlineVariantFile, a VCF by its media type. It is delivered with its index, so it is bgzf-compressed.

The genomics media types are text/plain and application/octet-stream, since these formats have none registered. The batch sets every flag to false, which the genomics classes fix anyway: none of them applies to sequence data.

Images and video

Facial photographs and gait videos contain biometric identifiers. Here, the acquisition table has none, so the batch sets containsBiometricIdentifiers: false. The video overrides it to true. Files with biometric identifiers never leave INTAKE.

The photograph uses FacialImagingFile, which always counts as biometric whatever the batch default, so it does not set the flag; the schema rejects it if it does. Its measurementTechnique is photography; a 3D facial scan uses the same class with surface_scan_3d, as an OBJ, STL, glTF or PLY model. The acquisition table is a DocumentationFile whose about points to the photograph.

Consent

A consent batch uses interaction: consent. Every subject row carries a consentRef, and the batch may include ConsentFiles listing the subjects they cover. Additional consent batch requirements remain undefined in the GOVERN register specification.

Restriction

Restrictions and withdrawals require no data files, a non-empty subject table and a noticeRef. The notice registered with GOVERN holds the restriction terms.
