Metadata sidecar tutorial

This tutorial builds a sidecar for a small registry deposit: one CSV file about three patients. Each step explains part of the document.

Tool-generated sidecars

The planned rddc-sidecar tool will generate and validate a sidecar from a batch directory and source descriptor. The draft command is rddc-sidecar generate ./batch --source rddc_source.json --batch-id 2026-11-reg01 --attest-direct-identifiers-removed. Generated and hand-written sidecars must pass the same checks.

Prerequisites

  • A source descriptor, rddc_source.json, issued by the RDDC at source registration. It contains the contributorId, sourceId, bucket and prefix pattern. See Source descriptor.
  • The JSON-LD context file, rddc_sidecar.context.jsonld.
  • A batch ID not previously used for this source, such as 2026-11-reg01.

Build the sidecar

  1. Arrange the batch files

    Arrange the files as they will appear under the S3 batch prefix. Use paths relative to this directory in the sidecar.

    2026-11-reg01/ └── registry/ └── patients.csv

    Check that no file or folder name contains a name, MRN or other identifier. Names like Jane_Doe_123.json are rejected at receipt.

  2. Set the document identity

    Create _sidecar.json in the batch directory. Copy the @context object from the downloaded context file into the sidecar. Give the document a new UUID and list the two specifications it follows.

    { "@context": "__ELIDED_CONTEXT__", "@id": "urn:uuid:0000a001-0000-4000-8000-00000000a001", "@type": "sc:Dataset", "conformsTo": [ "http://mlcommons.org/croissant/1.1", "https://w3id.org/rddc/sidecar/{{version}}" ] }

    Generate a UUID with python3 -c "import uuid; print(uuid.uuid4())" or uuidgen | tr A-Z a-z. It must be lowercase.

    Why embed the context?

    Copy the context unchanged. Embedding it keeps the sidecar self-contained and lets mlcroissant read it without fetching a remote context.

  3. Describe the batch

    Add the contributor, source, batch, upload location and interaction. Copy contributorId, sourceId and the bucket from the source descriptor.

    • url is the S3 batch prefix and must end with /. With the prefix pattern {sourceId}/{batchId}/ from the descriptor, that gives s3://rddc-deposit-ta2/src-ta2-01/2026-11-reg01/.
    • wasAttributedTo names the software that wrote the sidecar. For a hand-written sidecar, "@type" can be "sc:Person" or "sc:Organization", with the author or team name.
    • interaction is add for new data.
    • registerVersion is optional; copy it from the descriptor so a mismatch can be traced.

  4. Set sensitivity flags

    Set directIdentifiersRemoved to confirm that direct identifiers were removed before upload. Set contains* flags whose values are known; missing flags are treated as true.

    This registry has visit dates, so containsDates is true. Dates are accepted and masked at release.

  5. List the subjects

    Add one row per person, using their coded patient ID from the data. idSystem identifies the source of the ID; contributor-defined registry IDs use contributor.

  6. Describe the file

    Every data file needs a UUID, its path, size, media type, MD5 checksum and class. A SHA-256 checksum is optional. Get the size and checksums from the shell:

    stat -c %s registry/patients.csv # 4096 (macOS: stat -f %z) md5sum registry/patients.csv # 4dd68b0c… (macOS: md5 -q) sha256sum registry/patients.csv # optional (macOS: shasum -a 256)

    A registry table is a rddc:TabularFile. The class sets the modality, clinical_tabular, so the sidecar does not state it, and the file's name identifies the table.

    • @type is always cr:FileObject for a file. The RDDC class goes in additionalType.
    • contentSize is a string ending in " B".
    • name is by convention the same as contentUrl.
    • recordCount is optional: the number of rows, when known.

  7. Validate the sidecar

    Check the structure against the generated JSON Schema. Any JSON Schema validator works; for example:

    pip install check-jsonschema check-jsonschema --schemafile rddc_sidecar.schema.json 2026-11-reg01/_sidecar.json

    JSON Schema checks types, required fields, allowed values and conditional rules. The RDDC validator also checks file contents against checksums, missing or unlisted files, duplicate IDs and broken references. See validation checks.

  8. Upload, sidecar last

    Upload the data files first, then the sidecar. Uploading the sidecar signals batch completion and starts receipt.

    PREFIX=s3://rddc-deposit-ta2/src-ta2-01/2026-11-reg01/ aws s3 sync 2026-11-reg01/ "$PREFIX" --exclude _sidecar.json aws s3 cp 2026-11-reg01/_sidecar.json "$PREFIX"

    Correction and resubmission workflows remain to be defined.
