Documentation and other files

Files that describe other files, such as data dictionaries and READMEs, and the catch-all class for data no other class fits.

Documentation

A DocumentationFile documents other files: a data dictionary, an acquisition table for images, a codebook or a README. Its modality is metadata, so it is kept with the data rather than processed as data. Its content may be structured (a dictionary in CSV) or not (a README), so its structure is mixed.

When it documents particular files or record sets, about points to them by @id. A README for the whole batch leaves about out.

A batch of documentation files only may have an empty subject table, since such files hold no subjects' data. The registry recipe pairs a data dictionary with the record sets it describes.

Other data

A GenericFile is any data file no other class fits. Its modality is other: a curator decides how it is processed. A kind of data the RDDC receives regularly gets its own class in a later schema version, so if you use GenericFile often for the same kind of file, ask for a class.

A generic file is still checked like any other: its sensitivity flags apply, and unknown content is assumed to contain dates, postal codes, free text and biometric identifiers unless the batch or the file says otherwise.
