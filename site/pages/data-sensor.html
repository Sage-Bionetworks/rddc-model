Sensor data

Data recorded by wearables and other sensor devices: raw signals such as accelerometry or ECG waveforms, and measures derived from them such as step counts or sleep stages.

Raw signals and derived measures

Raw signals and the measures derived from them need different processing, so they are different classes:

  • A SensorSignalFile holds a signal before any aggregation, such as 100 Hz accelerometry, an ECG waveform or a sleep study's channels. Common formats are EDF/EDF+, WFDB, DICOM waveform and device or vendor formats. Those without a registered media type are application/octet-stream. Give the signal's sampling rate in hertz in samplingRate, Croissant's term; when channels differ, give the highest.
  • A SensorMeasureFile holds measures derived from a signal, such as per-minute step counts, sleep stages or daily heart rate summaries, as a table or JSON.

Techniques and devices

measurementTechnique lists the sensing techniques that produced the data. It is a list because one recording or summary can combine several. Values map to NCIT, OBI and SNOMED CT terms. The device that recorded the data, such as ActiGraph GT9X, goes in platform.

Standards

  • IEEE 1752.1 (Open mHealth) defines JSON schemas for sleep and physical activity measures. A file set of such measures declares it in conformsTo, from the pinned list.
  • Sensor data already in FHIR form, such as device Observations, is not sensor data in this sense: it goes in a FHIR file, in a file set that declares the HL7 Personal Health Device IG.

Sensitivity

Sensor data usually carries timestamps more precise than a year, which count as dates. Leave containsDates unset or true unless they have been removed.
