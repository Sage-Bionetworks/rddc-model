Sensor data

Data recorded by wearables and other sensor devices: raw signals such as accelerometry or ECG waveforms, in the format the device or study produced, and measures derived from them such as step counts or sleep stages.

Raw signals and derived measures

Raw signals and the measures derived from them need different processing, so they are different classes. A raw signal's format decides how it is read, so the format is the class too, under the abstract SensorSignalFile:

  • EdfSignalFile: EDF or EDF+, the usual format for polysomnography and EEG.
  • WfdbSignalFile: one file of a WFDB (PhysioNet) record, the .hea header or a .dat signal file. Keep the files of one record together in a file set.
  • DicomWaveformFile: a DICOM waveform object, such as a 12-lead ECG.
  • VendorSignalFile: a device maker's own format, such as ActiGraph .gt3x or Garmin FIT. platform, the device, is required, since it decides how the file is read.

Every signal file can set Croissant's samplingRate to the highest channel sampling rate, in hertz. A SensorMeasureFile holds measures derived from a signal, such as per-minute step counts, sleep stages or daily heart rate summaries, as a table or JSON.

Techniques and devices

measurementTechnique lists the sensing techniques that produced the data. The list supports recordings or summaries that combine techniques. Values map to NCIT, OBI and SNOMED CT terms. Set platform to the recording device, such as ActiGraph GT9X.

Standards

  • IEEE 1752.1 (Open mHealth) defines JSON schemas for sleep and physical activity measures. A collection of these measures can declare conformance to IEEE 1752.1.
  • Store sensor data already in FHIR form, such as device Observations, in a FHIR file, in a collection that declares the HL7 Personal Health Device IG.

Sensitivity

Sensor data usually carries timestamps more precise than a year, which count as dates. Leave containsDates unset or true unless they have been removed. Sensor formats have no field for an address, and a signal is not a biometric identifier under HIPAA Safe Harbor, so containsZipCodes and containsBiometricIdentifiers are false unless the file or the batch says otherwise. EDF+ annotation channels and WFDB header comments can hold free text; a measures table holds none unless it says so. See the flags by class.
