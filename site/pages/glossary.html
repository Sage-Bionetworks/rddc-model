Glossary and FAQ

Definitions and answers to common questions about sidecars.

Glossary

ACT
The RDDC team that registers sources and issues source descriptors.
additionalType
A schema.org property that gives a more specific type alongside @type. In a sidecar it names the RDDC class of a file or file set, such as rddc:OmopTableFile.
Batch
One delivery of files for one source, under one S3 prefix, with one sidecar. Also called a deposit.
C-CDA
Consolidated Clinical Document Architecture, an HL7 standard for XML clinical documents. The sidecar pins release 2.1.
Contributor
An organization that sends data to the RDDC. It has one bucket and one or more sources.
Croissant
An MLCommons metadata format for datasets, built on schema.org. The sidecar is a Croissant 1.1 dataset. See Foundations.
CURIE
A compact IRI such as cr:FileObject, where the prefix cr stands for http://mlcommons.org/croissant/.
Deposit sidecar
A sidecar written by a contributor for a batch they deliver.
Distribution
The list of every file and file set in a sidecar (schema.org distribution).
FHIR
Fast Healthcare Interoperability Resources, the HL7 standard for exchanging clinical data. The sidecar pins FHIR R4 (4.0.1) and US Core 6.1.0.
FileObject, FileSet
Croissant's classes for one file and for a group of files.
GOVERN
The RDDC governance service that registers withdrawal and restriction notices and consent.
Interaction
What a batch asks the RDDC to do: add, withdraw, restrict or consent.
IRI
Internationalized Resource Identifier: a web address used as a globally unique name for a term or thing.
JSON-LD
JSON for Linked Data. JSON plus @context, @id and @type, which tie keys and objects to IRIs.
Lane
A NORMALIZE processing path for one input format: 1 OMOP, 2 FHIR, 3 C-CDA, 4 other clinical tables.
LinkML
The modelling language the sidecar schema is written in. JSON Schema and the JSON-LD context are generated from it.
Modality
The kind of data a file carries, such as clinical_fhir or genomics.
NORMALIZE
The RDDC stage that converts accepted data into common models, by lane.
OMOP CDM
The OHDSI Observational Medical Outcomes Partnership Common Data Model. The sidecar pins version 5.4.
PROV
The W3C vocabulary for provenance. The sidecar uses it to name its author and link files or file sets to their inputs in the same batch.
Record set
Croissant's description of a table's columns (cr:RecordSet with cr:Fields).
schema.org
A shared vocabulary for structured data on the web. Croissant and the sidecar build on its Dataset type.
Sidecar
A metadata file that travels alongside data. Here, _sidecar.json.
Source
A contributor's data set with one set of use terms, registered before its first deposit.
Source register
The RDDC's record of every source, its use terms, access tier and delivery role.
Subject ID
The contributor's coded ID for a person. Never a name, MRN or other direct identifier, and never in a release.
Subject table
The sidecar's list of every subject in the batch (subjects).

Frequently asked questions

Is JSON-LD knowledge required to write a sidecar?

No. Paste in the context file unchanged and treat the rest as ordinary JSON. The validator checks it with JSON Schema.

Why is the context so large, and why embed it?

It contains the Croissant 1.1 context and RDDC terms. Embedding it keeps the sidecar self-contained and supports mlcroissant, which does not fetch remote contexts. Copy the @context object from rddc_sidecar.context.jsonld unchanged.

Are project-specific fields allowed?

Not at the top level of any object: unknown properties fail validation. Put project-specific values in additionalProperty with a key like ext:your_project:your_key. If a pipeline needs to make decisions on a value, propose it as a schema field instead.

Where do the license and access terms go?

Not in the sidecar. Use terms, access tier, de-identification class and date policy belong to the source and live in the source register, set by the ACT.

How are file IDs created?

Any lowercase UUID in the form urn:uuid:…. Keep a file's ID when the platform moves or re-registers it; give changed content a new ID. The RDDC tool can carry IDs forward when a previous sidecar is supplied.

Can one JSON sidecar describe 100,000 files?

A measured 120,000-file C-CDA batch produced about 93 MB of JSON. On an 8-core laptop with an SSD, generation took about 2.5 seconds and validation about 1.5 seconds, including checksums. Performance depends on the files and hardware. Large file sets can use globs instead of listing every member in hasPart; each file still appears in distribution.

How are incorrect uploads corrected?

The correction and resubmission workflow is still being designed. The current sidecar model has no correction fields.

Are OMOP foreign keys and FHIR references included?

No. The standards define them, and the declared conformsTo tells pipelines which version to apply. Use record sets only for joins between non-standard tables.

How are unknown sensitivity values handled?

Leave the flag out. An unset contains* flag is read as true, so de-identification checks for it.

Which class covers file types not listed here?

Use rddc:GenericFile with modality other. A curator decides how it is processed.

Where is the schema, and how are changes proposed?

schema/rddc_sidecar.yaml in the rddc-model repository. Open a pull request against it; JSON Schema, the context and this site are regenerated from it.
