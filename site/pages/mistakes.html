Common mistakes

Common metadata sidecar errors and how to fix them. The site build checks that JSON Schema rejects each invalid example.

RDDC class in @type

A file's @type is always cr:FileObject, and a file set's is always cr:FileSet, so that Croissant tools recognise them. The RDDC class goes in additionalType.

Rejected

Valid

Compression format in encodingFormat

encodingFormat is the media type after decompression. A gzipped FHIR NDJSON file is still application/fhir+ndjson; the gzip goes in compression.

Rejected

Valid

Numeric contentSize

Croissant writes sizes as strings with a unit. In a sidecar the unit is always bytes: "4096 B".

Rejected

{ "contentSize": 4096 }

Valid

{ "contentSize": "4096 B" }

Uppercase checksums

sha256 and md5 must be lowercase hexadecimal. Some Windows tools print uppercase; convert with tr A-F a-f.

Rejected

Valid

Absolute paths in contentUrl

contentUrl is relative to the batch prefix: no leading slash, no ... The batch location goes once, in the sidecar's url.

Rejected

Valid

A full s3:// URL is also invalid in contentUrl. The pattern in schema {{version}} does not yet detect this error.

HTTPS batch URL

The sidecar's url must be the s3:// form of the batch prefix, ending with a slash.

Rejected

Valid

Withdrawing without a notice

withdraw and restrict batches must name the GOVERN notice they carry out in noticeRef.

Rejected

Valid

Batch-only flags on files

synthetic and directIdentifiersRemoved describe the whole batch and can't be overridden per file. Only the contains* flags and notes are allowed in a file's sensitivity.

Rejected

Valid

Extensions without namespaces

Use ext:<namespace>:<key> for extension keys so projects can define their own values without name conflicts.

Rejected

Valid

Errors requiring the RDDC validator

These pass JSON Schema but fail the RDDC validator:

  • A file's subjectIds names someone who isn't in the subject table.
  • A file is missing from distribution or from disk/the bucket. The sidecar itself is never listed.
  • A file set lists a member in hasPart that isn't in distribution.
  • Two files share an @id, or the same subject appears twice.
  • A file set's conformsTo is not one of the pinned standards, for example http://hl7.org/fhir/R5.
  • directIdentifiersRemoved is false on data that isn't synthetic.
  • An inferred value is left unconfirmed.
  • A withdrawal, restriction or consent batch has an empty subject table.
