The RDDC data modelThe kinds of data the Rare Disease Data Commons accepts, how each is described, and the sidecar that lists a deposit.

Every file sent to the Rare Disease Data Commons (RDDC) belongs to a data class, such as a FHIR export, an OMOP table, a sequencing read file or a facial photograph. The class says what the file holds, which fields describe it, and what that means for processing and de-identification.

Each delivery of files comes with a sidecar, _sidecar.json, which lists every file with its class, checksum and subjects. The sidecar is a Croissant dataset with extra fields for clinical data.

Two parts

Data classes
One class per kind of file. A file names its class in additionalType, and the class fixes the accepted media types, the required fields and the file's modality. The data classes are documented first, by family: clinical, genomics, imaging, audio and video, sensor and documentation and other files.
The sidecar
One document per batch that lists every file, the subjects in the batch, and sensitivity facts for de-identification. It builds on the data classes: each entry in its distribution is a file of one class, or a set of such files.

What the sidecar is for

Contributors upload each batch to one S3 prefix, with the sidecar last. Its arrival starts automated receipt. The sidecar gives the platform the information it needs to check and route the files.

The platform needs to knowThe sidecar says
Has the upload finished?The sidecar is uploaded last. Its arrival starts receipt.
Did every file arrive intact?Each file is listed with its path, size and SHA-256 checksum.
How should each file be processed?Each file has a data class such as rddc:FhirNdjsonFile, which sets its modality. Genomics, imaging and sensor files also state the assay that produced them in measurementTechnique. Collections declare the standard they follow.
Whose data is this?A subject table lists every coded subject ID in the batch.
What does de-identification have to look for?Sensitivity flags: dates, ZIP codes, free text, biometric identifiers. Some classes identify a person whatever the flags say: genomic data, and facial images. See Files that identify a person.
Is this a data, withdrawal, restriction or consent batch?The interaction field.

The sidecar at a glance

File name and location
_sidecar.json at the root of the batch prefix, uploaded after every data file.
Format
UTF-8 JSON-LD. A valid Croissant 1.1 dataset, so generic Croissant tools can read it.
Scope
One sidecar per batch. One batch is one delivery of files for one source.
Schema
Defined in LinkML (schema/rddc_sidecar.yaml, version {{version}}, with the data classes in schema/data.yaml). JSON Schema and the JSON-LD context are generated from it.
Strictness
The schema is closed: unknown properties fail validation. Project-specific values go in namespaced extensions.
Contents
No direct identifiers or protected health information (PHI). Use coded subject IDs, never names or medical record numbers (MRNs).
Draft

Schema {{version}} is unreleased and may change before 1.0. This site is built from the schema in the repository, so the reference pages always match it.
