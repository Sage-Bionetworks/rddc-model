Example sidecars

These examples explain the main parts of a sidecar. make check validates them against JSON Schema and also checks Croissant compatibility when mlcroissant is installed.

Mixed deposit: FHIR, OMOP and registry

Site A's batch for src-ta2-01 contains a FHIR Bulk Data export, an OMOP CDM 5.4 snapshot built from it, and two registry CSVs.

The FHIR bulk export

Two NDJSON files, one per resource type, grouped in a FhirBulkExport set. The Observation file is gzipped, so compression is set while encodingFormat stays application/fhir+ndjson. It also contains free-text notes, so it overrides the batch's containsFreeText.

The OMOP snapshot

Each CDM table is an OmopTableFile with its cdmTable name. The OmopCdmInstance set requires the CDM version in conformsTo, the OHDSI vocabularyVersion, and the cdmSource fields an OMOP load needs. wasDerivedFrom records that this snapshot was built from the FHIR export above.

Registry tables and their join

The registry CSVs are TabularFiles in a TabularDataset. No standard says how they relate, so two Croissant record sets declare it: visits.patient_id references patients.id. The recordCount of visits.csv was detected by counting rows, recorded in valueOrigins.

Subjects

P0001 appears under two ID systems, once from FHIR and once from OMOP. Each (system, ID) pair is a distinct row.

C-CDA document set

Health information exchange documents, one XML file per patient encounter. CcdaDocumentFile requires subjectIds. The document type and template IDs stay in each document's header; the file set's conformsTo records the C-CDA release. The file set selects its members with a single glob instead of listing them, which keeps very large sets smaller. Every file is still listed in distribution.

Large batches

All file entries stay in the sidecar. A measured 120,000-document C-CDA batch produced about 93 MB of JSON. Consumers can stream the document if needed.

Withdrawal

A withdrawal lists the subjects to remove and the GOVERN notice that authorizes it. It carries no data files, so distribution is an empty list. The sensitivity block is still required.
